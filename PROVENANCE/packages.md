## Verification (10 Oct 2026)

- Every tarball's sha256 (x to ab on 10 Oct morning, ac at midday) matched its `.sha256` file in Downloads.
- Every tarball was extracted and diffed (`diff -rq`) against `git archive` of
  the HEAD listed above. x to ab are identical except for the empty folder
  `v2/Experimental observations/Kantola nitrogen`, which the build script adds
  because git does not track empty directories.
- ac (pkg/ac at cbf3626) is identical to its tarball in every file except the two
  pin lists `runtime/Base_1D/shared_pins.sha256` and `ssp_pins.sha256`: the
  commit carries stale pins (2 and 7 entries fail `sha256sum -c` against the
  commit's own files), while the tarball's pins were regenerated by the build
  script and validate. The code and notes are the same; only the pin files
  differ. A deployment built from pkg/ac rather than from the tarball would
  fail the pin check until the pins are regenerated and committed.
- The tarball READMEs and RUNBOOKs do not record a commit sha; the content diff
  above is the verification.
